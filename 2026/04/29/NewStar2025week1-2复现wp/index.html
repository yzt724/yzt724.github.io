Week1

EzMyDroid

下载下来显示文件错误，所以没有复现

Puzzle

exe文件，首先使用Exeinfo PE查看该文件的位数，是32位还是64位，有upx壳没有

64位，无壳，直接使用对应的ida打开，（Fn+）F5反编译打开main函数，发现提示语

根据提示，进入Puzzle_Challenge函数，找到flag的第一部分Do_Y0u_

找到flag的第二部分Like_7his_Jig

发现flag的第三个部分的有关信息

点击encrypted_array查看数组内容，直接打开发现是奇怪的中文字，这是因为IDA 错误地把那一串十六进制数据当成了中文来显示

点击快捷键D，转换为16进制后提取出来

根据信息写脚本，得到flag的第三部分s@w_puzz代码

shift+f12查看字符串，发现第一行是一个奇怪的字符串

双击过去发现提示，找到flag的第四部分1e_Gam3

组合起来就是Do_Y0u_Like_7his_Jigs@w_puzz1e_Gam3，再包上flag头，得到flag{Do_Y0u_Like_7his_Jigs@w_puzz1e_Gam3}

Strange Base

64位，无壳，ida打开，f5反编译

main函数中，给出了enc（密文）=”T>6uTqOatL39aP!YIqruyv(YBA!8y7ouCa9=”，用户输入input，调用base64_encode进行加密后得到output，比较output与enc是否相等，如果相等则显示”Oh! You’re awesome!!!”

分析base64_encode函数，发现是标准的base64加密

查看索引表，发现是自定义的索引表，提取出来索引表

写脚本解密，得到flag{Wh4t_a_cra2y_8as3!!!}（注：使网站解密可能会提示解密失败）

X0r

64位，无壳，ida打开，f5反编译

分析main函数

第一层加密：遍历用户输入，根据 i % 3的不同结果，走向不同的分支，进行不同的异或加密

这段代码的核心在于 i % 3（i 对 3 取余数），余数只可能是 0, 1, 2。

  • **如果 i % 3 == 0**（即第 1, 4, 7… 个字符）： 执行 else 分支：Str[i] ^= 0x14u;
  • **如果 i % 3 == 1**（即第 2, 5, 8… 个字符）： 执行 if ( i % 3 == 1 ) 分支：Str[i] ^= 0x11u;
  • **如果 i % 3 == 2**（即第 3, 6, 9… 个字符）： 执行内部的 else 分支：Str[i] ^= 0x45u;

第二层加密：定义了一个包含 3 个整数的数组 v5，遍历用户输入，对每个字符进行异或操作

**j % 3**：这是一个“取模”运算，它会让索引值在 0, 1, 2 之间不断循环。

  • 当 j = 0, 3, 6... 时，j % 3 = 0，使用的是 v5[0] (19)。
  • 当 j = 1, 4, 7... 时，j % 3 = 1，使用的是 v5[1] (19)。
  • 当 j = 2, 5, 8... 时，j % 3 = 2，使用的是 v5[2] (81)。

根据之前讲过的知识，xor是对称加密，对密文再进行一次同样的加密即可得到明文，写脚本解密得到flag{y0u_Kn0W_b4s1C_xOr}

plzdebugme

elf文件，64位，ida打开，发现提示在xor函数中可以找到flag，在xor函数处下断点（f2）

动调的准备步骤见下文

开始动调，光标停留在xor函数处，按f7步入函数

在 flag[32] = 0;处下断点，直接f9运行到flag[32] = 0;处

然后查看flag数组的内容，发现flag{It3_D3bugG_T11me!_le3_play}

elf动调的步骤

因为文件是elf文件，需要在虚拟机上远程动调，虚拟机和ida需要的准备步骤分别如下

虚拟机

ubuntu（kali是找到tmp文件夹，新建re文件夹，其他步骤一样）

在home下新建re文件夹，把题目拖进去，在本机上找到linux_server64文件，在IDA\dbgsrv\linux_server64路径下，也拖进去

然后右键，点击Open in Terminal（打开终端)，执行

示例如图

ida

选择对应的动调方式，Remote Linux debugger

点击图中的绿色三角或者按f9，出现如图所示的弹窗

Application：填该文件在虚拟机中的文件地址

Input file：同上

Directory：填该文件在虚拟机中的文件夹地址（注：跟之前两个不一样）

Parameters：不用填

Hostname：填使用ip addr命令查到的虚拟机ip地址

Port：默认23946

填好后点击OK，开始动调

Forgotten_Code

分析main函数，str1（flag）经fn（TEA）加密处理后等于ezgm

分析fn函数，一个对密钥key处理过的TEA加密函数

解密脚本，flag{4553m81y_5_s0o0o0_345y_jD5yQ5mD9}

  2. 对ezmg进行TEA解密得到str1（flag）

对用户输入进行下标混淆后，赋值给v6，v6需要等于v7（已给出），找到混淆的规律，把v7还原得到正确的flag。

找混淆的规律时，结合题目提示要动态调试，可以输入一个没有重复字符的flag，提取出来混淆后的对应的密文，以此找出规律。

采一朵花，送给艾达（1）

存在花指令

花指令为：基于互补跳转的永真/永假跳转+字节错位，nop掉140001785-87

基于互补跳转的永真/永假跳转：根据代码可知，程序一定会执行jz跳转，jnz一定不会跳转，jnz存不存在效果一样，这就是花指令，nop掉jnz

字节错位：jz跳转到的地方是loc_140001787+1，loc_140001787=140001787，也就是说jz要从执行140001788开始执行，所以需要把140001787的对应的字节nop掉，从140001788开始才是真正执行的有用的内容

第二个花指令，nop掉了140001808-16

存在与第一个花指令相同的永真/永假跳转+字节错位，但还包括

此时会变成这样，这是因为jz short loc_14000180D跳转到的地方是nop后的指令，不会有指令被执行，jz白跳转了，也需要nop，

call指令要执行的，0F848DB1Ah 地址是非法的，这种情况一搬是因为插入了一个0xE8的字节码，ida把其识别成了call，把0xE8字节nop掉，重新识别函数

main函数成功反汇编后，分析，发现rc4_init函数也存在花指令，跟mian函数中的第一个花指令相似，同样的处理办法

rc4_crypt函数，跟mian函数中的第一个花指令相似，同样的处理办法

四处花指令处理完毕后，分析main函数，一个rc4加密，密文给出
